# Changelog plugin

What changed in the factory, one plain line each, so the owner can see what changed without reading every merge. Its rows are merged PRs, versions on main, rules, settings and ops changes, in the dashboard's local Postgres (`changelog_entry`, and `changelog_seen` for each viewer's last look). A merge's row also holds its `detail` (a few short lines of Markdown, at most 6) and its `images` (`[{id, alt}]`), the ids of its before and after screenshots, which live in `changelog` in the data folder (or `$PLAYGROUND_CHANGELOG_DIR`, which a live-reads test stack points at a scratch folder; 0700, each file 0600) and never in the database.

## The page

`/dashboard/apps/changelog` (`web/next/src/plugins/changelog/`): its title and no subtitle, then the changes grouped by version beside the picked one in full, half and half. Each version is one accordion row on the shelf classes in `web/next/src/components/shelf.ts`: its tag or merge icon, its name, its date and its count, the top row open and the rest folded, every version left open while a search or filter is set, and a linked entry's version open (the owner: "changelog should look like inbox, like the accordions"). Each line starts with its kind's mark, so the kind takes no column; the Kind filter shows each kind's count and only the kinds there are. A version a search or filter leaves empty is hidden whole, and when nothing matches one stock `Empty` says No changes match with Clear filters. The detail renders through `TranscriptMarkdown`, so no image loads from elsewhere and a link opens as a transcript's does. Opening it marks every change it shows read for that viewer (`POST /api/v1/apps/changelog/seen`), except on `bun run verify`'s own visit, which signs in as the same one user and would clear the owner's count after every merge (its browser sets `VERIFY_VISIT`, `web/next/src/lib/verify-visit.ts`, before each page runs), and the aside's Changelog square counts the rest (`GET /api/v1/apps/changelog/unread`, through `web/next/src/plugins/registry.ts`). Screenshots load only from `GET /api/v1/apps/changelog/images/:id`. Each `#<n>` in the aside's line and detail links to that issue in the entry's repository (`linkIssues()`, `issueParts()` in `groups.ts`; GitHub sends a PR's number on to the PR), the detail's through `TranscriptMarkdown`. The picked change is in the URL by a name a person reads (`?entry=pr-253`, `?entry=v0.0.9`; `entrySlug()` in `groups.ts`), and an older link by its id still opens it. On a phone the drawer follows that parameter: a link opens it on first load, and closing it drops `?entry=` (`bun run verify changelog-entry` checks both at 390px).

## Switch

On by default (`features.changelog` in `packages/config/src/site.ts`). `CHANGELOG_ENABLED=false` in the root `.env` turns it off: `GET /api/v1/apps/changelog` answers 404 and `bun run changelog` writes nothing.

## Where its rows come from

No model writes a line; each is at most 15 words (`MAX_WORDS` in `sources.ts`).

- `bun run changelog sync`: every PR merged into `canary` from the first one it tracks on, but the publish step's own bookkeeping (a `ci(changelog)`, `ci(version)` or `ci(release)` PR, which its version's group stands for; any other `ci(...)` PR is a change like the rest), and every published version on main it lacks, idempotent by source key (`pr:<owner>/<name>#<n>`, `release:<tag>`). A PR's line is the first bullet of its body's `## TL;DR`, or a prose TL;DR's first sentence, or the `Outcome:` line a TL;DR or an older body opens with, which wins where a body holds both (`outcomeLine()`), held to the cap (`leadLine()`: its first sentence, else its longest lead that ends at a whole clause, else cut), and its title only when it has no such line; a person listed in `CHANGELOG_PEOPLE` reads "a teammate" there before the cut (`withTeammates()`: the longest name first, matched whole, so a letter, combining mark or digit of any script beside it makes another word, a handle with its `@`, any `user@host` address naming one whole, and an http or https link kept as written, so a listed name inside a link still shows). Its detail (`detailOf()`) is Markdown, at most 6 lines: a lead paragraph (another `Outcome:` paragraph, else the paragraph of the entry's own line (`outcomeLine()`), or a prose TL;DR, past its first sentence, or whole when that line was shortened, else the prose paragraph right after the line's; two sentences beside bullets, four alone, plus the whole first sentence when the line was shortened), then the top-level bullets of its What changes section (What, What changed, What it does, What ships, Changes, Fix), each its first sentence, and the next with it when the first is its bold label alone, else its bold label of three words or more when those words are dropped, at most 25 words, or with no such section its TL;DR's bullets past the first, all of them under an `Outcome:` line; a cut, here or in the line, never leaves a bracket, quote or code span open. A repository path comes out only as an aside (a parenthetical of paths, or a path closing its clause after a preposition), and a sentence or bullet that holds a path as a word of it is dropped; a link keeps its URL only when it is http or https, and a sentence or bullet naming an agent (`site.name`, today's manager and dispatcher names (`getSessionNames`: the aliases and each name set apart from its role word), a sin or its Latin form (`SINS`, held to the leak hook's `extensions/core/lists/playground-terms.json`), an `@Name` mention, or a `worker-`, `reviewer-`, `tester-`, `runner-` or `probe-` name), the factory, the owner (`OWNER`) or a person listed in `CHANGELOG_PEOPLE` is dropped, read by its link text so a link to this repository keeps its line; so is a source quote, a line of issue references, and every attribution line (the generator's footer, a `Co-Authored-By:` line, a squash message's trailers). A merge whose body gives none takes its squash commit's (`commitDetail()`, one `gh api` read of the merge commit), read when the merge is new to the changelog. A merge new to the changelog has its screenshots copied: the `github.com/user-attachments` images whose alt text says before or after, from its body and then the first owner comment holding any, at most 6. A private repository's image needs a token, so the sync sends gh's own (`gh auth token`, held in memory) to github.com alone and fetches the signed storage URL it redirects to without it; a file that is not a PNG, JPEG, GIF or WebP is refused by its bytes. A row already there only gains a detail or screenshots it lacked. A version's line counts the PRs its notes link. Ops runs it every 5 minutes.
- `bun run changelog seed`: the one-time seed, safe to run again: a sync with the lines drafted in `seed.json` in place of the PRs' own, plus the rules of 6 Oct (each line read through `withTeammates()` as a PR's is), which also copies the screenshots of any merge already there without them (run it once after the detail and images columns land, to fill the rows synced before).
- `bun run changelog seed --refresh-detail`: the seed, rewriting every merge's line and detail by today's rule (reading the squash commit of each merge whose body gives none) in place of the ones it holds, a detail of none included, so a line or detail an older rule wrote goes, though a merge whose commit it could not read keeps its own line and detail; and removing the rows of merges the sync no longer keeps, such as the publish step's bookkeeping and the merges into main, between the lowest and highest PR numbers it read (a row older than the newest 1000 merges, or one a sync added while it ran, is never touched). A second run rewrites and removes nothing. Run it once on the live Dashboard after a change to the rule.
- `bun run changelog add --kind ops|rule|setting --text "<one line>" [--link <url>] [--actor <name>]`: a line by hand, with no source key, so two identical calls add two rows, and no refresh rewrites it: its text stays as typed, a listed name included.
- `bun run changelog fixture`: a test stack's made-up rows (`fixture.ts`), replaced at the current time, one with a detail and two drawn screenshots the API serves from memory; refused on a stack that reads this machine.

`sync` and `seed` read GitHub, so they run only on a stack that reads this machine (the live Dashboard's checkout, a person's own clone, or `PLAYGROUND_LIVE_READS=true`; ADR 0008): a fixture stack's database never holds real lines. Each command proves `POSTGRES_URL` is a Postgres container on this machine published on loopback alone (`provenLocal`, as `bun run ingest` does) before it reads or writes.

## Remove it

1. Delete this folder, its two lines in `api/hono/src/plugins/registry.ts` and its key in `SWITCHES` (`switch.ts`).
2. Drop `changelog` from `features`, `CHANGELOG_ENABLED` from `packages/env/src/api-hono.ts`, `turbo.json` and `.env.example`, `bun run changelog` from the root `package.json`, and its rows in `packages/scripts/src/verify/dashboard-map.json` (the page and the unread route).
3. Delete `packages/db/src/schema/changelog.ts` and its export, run `bun run db:generate`, which drops both tables, and `bun run db:migrate`. By hand, the drop is `drop table changelog_seen; drop table changelog_entry;`. Delete the screenshots folder, `changelog` in the data folder.
4. On the web, delete `web/next/src/plugins/changelog/`, its line in `web/next/src/plugins/registry.ts`, the page under `app/(protected)/dashboard/apps/changelog/` and its entry in `web/next/src/lib/apps.ts`.
